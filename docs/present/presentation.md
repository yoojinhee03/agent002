## Section 2 — 문제 인식 (3장 / 5분) [DOCX §1]

### Slide 3 — 출시 배경: "에이전트를 만드는 빌더" 의 부재가 우리 출발점

- **핵심 메시지**: 이전 프로젝트에서 매번 **Skills·프롬프트·도구 연결을 손으로 수정**하며 에이전트를 구현하던 경험이 누적되며 "**에이전트를 만드는 에이전트(Builder)**" 의 부재가 가장 큰 병목으로 드러났다. 이번 MVP 아이디어 회의에서 거론된 시나리오 대부분이 **오늘 보여드릴 Agent Builder 로 그대로 구현 가능**하다는 점을 확인하며 본 프로젝트가 시작됐다.
- **시각자료**: 좌측 — **3단 타임라인**: ① 이전 프로젝트(반복적 Skills/프롬프트 수동 튜닝 → 매 시나리오마다 동일 작업 반복) → ② 회고에서 "빌더가 있었다면" 결론 → ③ 이번 MVP 의 Agent Builder. 우측 — **이번 MVP 아이디어 회의 산출물 매핑 표** (회의에서 나온 시나리오 N개 / Builder 로 구현 가능 비율 / 남는 항목).
- **말할거리**:
  - 이전 프로젝트 경험 — Skills 정의·프롬프트 튜닝·도구 연결을 매번 코드/설정으로 수동 처리 → 새 시나리오마다 처음부터 다시
  - 빌더가 있었다면 그 시간 대부분을 "에이전트를 짜는 일" 이 아니라 "**비즈니스 문제 정의**" 에 쓸 수 있었음 — 이 회고가 본 MVP 의 출발점
  - 이번 MVP 아이디어 회의에서 거론된 시나리오 — 영업 리서치·내부 문서 Q&A·고객 응대·운영 자동화 등 — **대부분이 Agent Builder 의 자연어 → 캔버스 자동 조립 흐름으로 구현 가능** 함을 사내 검증
  - 핵심 통찰: "**도구를 잘 쓰는 사람 = 빌더를 가진 사람**" — 이 격차가 곧 우리가 노리는 시장 기회
- **소요 시간**: 1분 30초

### Slide 4 — 시장 진단: RAG 솔루션은 포화, Agent Builder 는 공백

- **핵심 메시지**: 국내외 시장은 **시나리오 기반 RAG 솔루션으로 포화 진입** 중이지만, **자연어로 에이전트를 만드는 빌더(Agent Builder)** 는 글로벌에서도 Google **Gemini Enterprise Agent Platform**(전 Vertex AI Agent Builder) 과 **Dify** 두 곳이 사실상 전부다. 국내는 그 공백이 더 크다. 우리는 **운영 통제·국산 환경 최적화** 로 그 공백을 선점할 수 있다.
- **시각자료**: 상단 좌·우 2분할, 하단 한 줄 시그널 띠.
  - **좌 — 시나리오 RAG 솔루션 (포화)**
    - 글로벌·국내 다수 SI / 스타트업이 동일 카테고리에서 경쟁
    - 시장 규모: **2025 $1.94B → 2030 $9.86B, CAGR 38.4%** (MarketsandMarkets), 2026 시점 $3.33B
    - 한국은 RAG 도입 선도국 — 제조·고객지원·미디어 분야 파일럿 다수
    - 차별 어려움 — 기능·UX 가 유사화
  - **우 — Agent Builder 솔루션 (공백)**
    - **Google Gemini Enterprise Agent Platform** (2026 Cloud Next 에서 Vertex AI Agent Builder 리브랜딩) — 200+ 모델, ADK + Agent Studio(저코드) + Agent Engine 통합
    - **Dify** — 2026.03 $30M Series Pre-A, 280 enterprises · 1.4M deployments, 한국은 2026.03.07 AWS 강남 사옥 첫 밋업(130명)·삼성전자 air-gapped 사례 공개 → **한국 시장은 초기 진입 단계**
    - COEX AI EXPO 2026 현장 관찰: 자연어 → 캔버스 자동 조립을 가진 빌더는 위 두 진영뿐, 그 외는 RAG·챗봇·워크플로 자동화로 회귀
  - **하단 — RAG vs Agent Builder 본질 비교**:
    | 축 | 시나리오 RAG | Agent Builder |
    |---|---|---|
    | 흐름 | retrieve → generate (결정적) | plan → act → observe (자율 다단계) |
    | 도구 사용 | 검색·인용 중심 | 외부 시스템과 다단계 작동 |
    | 운영 난이도 | 수 주 | 수 개월 (거버넌스 필요) |
    | 시장 성숙도 | 포화 진입 | **초기·공백** |
- **말할거리**:
  - 국내에서 흔히 보이는 "AI 솔루션" 대부분은 **시나리오 기반 RAG** — 시장은 빠르게 자라지만 변별이 어려워짐
  - **Agent Builder 는 본질이 다름** — RAG 가 "정보를 잘 찾아 답한다" 면 Agent 는 "정보를 찾아 → 판단해 → 외부 시스템을 움직인다"
  - Google 은 Gemini Enterprise Agent Platform 으로 완성도 높은 빌더를 내놓았지만 **외산 SaaS / 클라우드 종속**, Dify 는 오픈소스지만 **거버넌스·국내 보안 요구 적합성**에서 갭이 있음
  - Gartner: **거버넌스가 약한 Agent 프로젝트의 취소율 상승** — 우리 6대 기능(HITL·도구 권한·SubAgent)이 정확히 그 공백을 메움
  - 결론: **국내 환경에 맞는 통제·감독·국산화 강점을 가진 Agent Builder** 가 비어 있는 자리 — 지금이 선점 창
- **소요 시간**: 2분

### Slide 5 — 타깃 시장 & 1차 ICP

- **핵심 메시지**: 1차 고객은 "사내 업무에 AI 에이전트를 도입하려 하지만 **보안·통제 요구가 높아 Google/Dify 를 그대로 못 쓰는** 중대형 조직"이다. RAG 시장이 포화하는 동안 **Agent Builder 시장은 두 자릿수 CAGR 초기 시장** — 선점 의미가 크다.
- **시각자료**: 좌측 — 동심원 GTM 다이어그램 (내부(우리) → 그룹사 → 외부 고객) + ICP 페르소나 1-2개 (CIO·CDO·보안 책임자). 우측 — **시장 규모·시그널 카드 3장**.
  - **AI Agents / Agent Builder 시장** — 빠른 두 자릿수 CAGR 의 초기 시장 (MarketsandMarkets / Grand View Research / Precedence Research 인용, docx 에서 단일 1차 출처 확정). 비교 앵커로 인접 **RAG 시장 CAGR 38.4%** (MarketsandMarkets)
  - **엔터프라이즈 채택 시그널** — Gartner: agentic AI 가 향후 수년 내 엔터프라이즈 애플리케이션의 상당 비중에 포함되는 한편 **거버넌스 부재 Agent 프로젝트의 취소율 상승** 경고 (Hype Cycle / Top Strategic Tech Trends 시리즈, 최신 연도 1건 인용)
  - **국내 시그널** — Dify 한국 첫 밋업 2026.03 / 삼성전자 air-gapped 배포 사례 공개 → 국내 대형 조직이 **외산 빌더를 사내망에 들이기 시작**한 시점. KISDI / KOSA / NIA 의 국내 생성형 AI 도입·보안 통계 인용 예정
- **말할거리**:
  - 1차 ICP: 통제·감사 요구가 높아 Google/Dify SaaS 를 그대로 못 쓰거나, 들이더라도 **국내 환경 최적화·통제 레이어가 필요한 중대형 조직**
  - 사용 시작점: 영업·고객지원·내부 리서치·운영 자동화의 1개 워크로드
  - 시장 규모는 기관별 정의(에이전트 SW 만 / 인프라 포함 등)에 따라 차이가 있어 **단일 출처 인용 + 정의 범위 명시**가 docx 작성 원칙
  - 핵심 시그널은 절대 규모보다 **Agent Builder 가 한국에 막 진입한 시점**과 **거버넌스 부재로 인한 Agent 프로젝트 취소 위험** — 우리가 자리 잡을 창이 열려 있음
- **소요 시간**: 1분 30초

## Section 3 — 주요 서비스 내용 (8장 / 8-10분) [DOCX §2]

### Slide 6 — AgentStudio 한 장 정의

- **핵심 메시지**: AgentStudio는 **자연어로 에이전트를 만들고(Agent Assistant), 6가지 기본 기능으로 통제·운영하는** 엔터프라이즈 플랫폼이다.
- **시각자료**: 가치제안 4축 — ① **셀프 빌드(Agent Assistant)** ② 통제권(Control) ③ 재사용(Reuse) ④ 감독(Oversight) — 가운데에 AgentStudio 박스.
- **말할거리**:
  - 우리는 "에이전트를 더 똑똑하게"가 아니라 "에이전트를 **누구나 만들고 안전하게 운영하게**"에 베팅
  - **Agent Assistant** 가 진입 장벽을 없앤다 — 캔버스 수동 설정 없이 자연어로 메인+서브+도구 자동 조립
  - 모델/벤더 종속을 피하고 운영 레이어를 가져감
  - 사내 첫 사용자가 우리 자신 — 도그푸딩으로 검증
- **소요 시간**: 1분

### Slide 7 — 경쟁·대안 포지셔닝

- **핵심 메시지**: AgentStudio는 **"자연어로 만들기(셀프 빌드)" + "기업이 통제·운영 가능"** 두 축을 동시에 충족하는 자리에 단독으로 있다.
- **시각자료**: 2×2 포지셔닝 매트릭스 — X축: **셀프 빌드 용이성**(개발자→비개발자), Y축: **엔터프라이즈 통제력**(낮음→높음). 자리:
  - LangChain raw / LangGraph 코드 — 셀프 빌드↓ / 통제력↑ (좌상)
  - Dify / Flowise / 노코드 빌더 — 셀프 빌드↑ / 통제력↓ (우하)
  - 사내 자체 빌드 — 셀프 빌드↓ / 통제력↑ (좌상, 확장성 ↓)
  - **AgentStudio** — 셀프 빌드↑ / 통제력↑ (우상단, **단독**)
- **말할거리**:
  - 코드 프레임워크: 유연하지만 비개발자는 손도 못 댐
  - 노코드 빌더: 쉽지만 권한·HITL·Skill 같은 운영 통제권을 양도
  - **AgentStudio 차별점**: Agent Assistant 로 비개발자도 자연어로 에이전트를 짜고, 그 위에 6대 기능으로 통제권을 지킨다
  - LangGraph·deepagents 공식 패키지 위 — 표준 이탈 위험 낮음
- **소요 시간**: 1분 30초

### Slide 8 — 서비스 정의 & 핵심 기능 매트릭스

- **핵심 메시지**: AgentStudio는 Slide 4 가 지적한 **거버넌스 갭(Agent 프로젝트 취소율의 주된 원인)** 을 6대 기능으로 정면 해소하고, 다음 슬라이드의 **Agent Assistant 가 이 6개를 자연어 한 마디로 자동 조립**한다.
- **시각자료**: 슬라이드 표시 타이틀 "**업무 목표를 이해하고 실행계획을 세우는 Agent**" (※ 'Agent Builder'는 제품 카테고리 표현으로만, 본문·카드는 **Agent Assistant**로 통일 — 이름 규칙 참조). 6개 카드 3행×2열 그리드 + 하단 캡션 띠.
  - **Multi Agent Routing** — Main Agent 가 작업을 SubAgent 에 위임. 격리된 컨텍스트·도구·모델 → **컨텍스트 격리로 비용·정확도 보호** + 보안 격리
  - **Tools** — HTTP·Code·Search·Built-in **내장 도구** + 도구별 권한 매트릭스(자동/HITL/차단) ※ 외부 시스템 연동은 MCP 카드
  - **Skills** — 지침+도구+버전을 묶은 재사용 능력 단위. 버전 핀으로 운영 안전 + export/import 로 조직 자산화
  - **MCP** — Gmail·Slack·Drive 등 외부 시스템을 표준 프로토콜로 연결. 사용자별 자격증명 격리·OAuth 관리
  - **보안 및 통제** — Sandbox 격리 실행 + HITL 게이트 + I/O 가드레일 + 감사 로그 → Gartner 거버넌스 갭 해소
  - **사용자 친화적 UI** — 자연어 빌더(Agent Assistant) + 캔버스 시각 편집 + Todo 실시간 가시화 → 비개발자 셀프 빌드
  - 하단 캡션 띠: "위 6개를 자연어 한 마디로 자동 조립하는 것이 **Agent Assistant** — 다음 슬라이드의 핵심"
- **말할거리**:
  - **MCP 를 Tools 에서 분리해 별도 카드로** — "내장 도구(Tools) vs 외부 시스템 연동(MCP)" 로 깔끔하게 구분 (MCP 는 기술적으로 Tool 유형의 하나지만, 외부 연동 어필이 커서 별도 강조)
  - 거버넌스 차별축은 **Multi Agent Routing · Tools 권한 · 보안 및 통제** 3개 — 외산 Builder(Google/Dify) 대비 우리 강점
  - **Skills · 사용자 친화적 UI** 는 도입 후 가치를 키우는 자산화·생산성 축
  - "직접 손으로 조립하는 게 아니라 자연어 한 마디로 자동 조립된다" → 다음 슬라이드 Agent Assistant 로 연결
- **소요 시간**: 1분 30초

### Slide 9 — Agent Assistant: 에이전트를 만드는 에이전트 (헤드라이너 차별화)

- **핵심 메시지**: 사용자가 자연어로 시나리오를 말하면 Agent Assistant 가 **메인 에이전트 + 서브에이전트 + 도구 + Skill 까지 캔버스에 자동 제안**한다. 이것이 AgentStudio 의 결정적 차별점이다.
- **시각자료**: 좌우 분할.
  - **좌**: 채팅창에 사용자 자연어 한 문장 ("주간 경쟁사 동향 정리해서 슬랙에 보내주는 에이전트 만들어줘")
  - **우**: 캔버스에 메인 노드 + 서브 노드 2개(`research` / `report-writer`) + 연결 엣지가 자동으로 그려진 모습. 노드들이 "proposed" 배지로 표시.
  - 아래 띠: 4-action 분류 칩 — **clarify / create_agent / edit_agent / answer_directly**
- **말할거리**:
  - 진입 장벽 제로 — 캔버스를 직접 끌어다 놓을 필요가 없다
  - **다중 턴 명확화** 지원 — 모호하면 먼저 묻는다 (`clarify`), 의도가 명확하면 바로 자동 생성 (`create_agent`)
  - **부분 수정도 자연어** — "프롬프트에 출처 명시 한 줄 추가", "MCP Slack 도구 켜줘" (`edit_agent`)
  - 메타 질문도 처리 — "이 에이전트 지금 뭘 할 수 있어?" (`answer_directly`)
  - 안전장치 — 카탈로그에 있는 도구·Skill id 만 사용 (hallucination 방지)
  - 확인 UX 는 채팅 inline — 별도 모달/배너 없이 흐름 끊지 않음
  - **현장 한 마디**: "노코드 빌더 + 코드 SDK 의 장점만 가져왔다"
- **소요 시간**: 2분

### Slide 10 — 데모 스토리보드 #1: SubAgent × HITL

- **핵심 메시지**: Agent Assistant 가 만들어준 에이전트가 실제로 동작하는 모습 — 서브에이전트에게 리서치 위임 + **위험한 행동은 사람이 가로채는** 운영 패턴.
- **시각자료**: 시나리오 스토리보드 4컷 — ① (앞 슬라이드 Agent Assistant 가 만든) 에이전트 실행 시작 ② 메인 → `research` 서브에이전트 위임 ③ 결과 정리 후 슬랙 전송 직전 **HITL 카드** 발생 ④ 사람이 Approve/Edit/Reject 선택. 화면 한 켠에 Todo 패널이 실시간 갱신되는 모습.
- **말할거리**:
  - 앞 슬라이드에서 "만든" 에이전트가 그대로 "운영"으로 이어진다 — 자연스러운 연결
  - SubAgent는 독립 컨텍스트라서 메인이 토큰을 낭비하지 않음
  - HITL은 도구별 정책 — 검색은 자동, 외부 전송은 사람
  - 의사결정 로그가 그대로 감사 추적
- **소요 시간**: 1분 30초

### Slide 11 — 데모 스토리보드 #2: Skills × Tools

- **핵심 메시지**: 한 번 만든 "능력 묶음(Skill)"을 여러 에이전트에 장착하고, 도구는 권한 정책으로 통제해 **자산화·통제를 동시에** 달성한다.
- **시각자료**: 좌측 Skills 카탈로그(예: "재무 보고서 작성", "고객 대응 톤"), 우측 두 에이전트가 동일 Skill을 장착·버전 핀하는 그림. 아래 Tools 권한 매트릭스(자동승인 / HITL / 차단).
- **말할거리**:
  - Skill = 프롬프트 조각 + 예제 + 전용 도구를 묶은 재사용 단위
  - 버전 핀 — Skill을 바꿔도 운영 중 에이전트가 깨지지 않음
  - 도구 권한 매트릭스 — 누구도 임의로 결제 API를 호출 못 함
  - Agent Assistant 가 Skill 도 같이 추천·자동 장착 → 자산이 자연스럽게 쌓임
- **소요 시간**: 1분 30초

### Slide 12 — 시스템 아키텍처 1장

- **핵심 메시지**: AgentStudio는 **Web(28002) / API(28001) / Runner(28003) 3-tier**로 분리돼 있고, 실행 엔진은 검증된 공식 패키지 위에 있다.
- **시각자료**: 3-tier 다이어그램 — Next.js 16 Web → NestJS API → FastAPI Runner(LangGraph + deepagents) → PostgreSQL 16 + Redis. Agent Assistant 도 Runner 안의 별도 모듈(`agent_assistant`)로 표시. WebSocket 이벤트 화살표(`agent.streaming` / `step.progress` / `run.completed` / `node.proposed`) 표시.
- **말할거리**:
  - 관리 API와 실행 엔진을 분리 — 다중 모델·다중 테넌트 확장 용이
  - 실행 엔진은 LangGraph + 공식 deepagents 패키지에 정렬 — 표준 이탈·재구현 비용 낮음
  - Agent Assistant 도 같은 Runner 안에서 도구 호출(`propose_main_agent` / `propose_sub_agent`) 패턴으로 동작 — 코드 중복 없음
  - 모든 실행 이벤트가 WebSocket으로 일관 표준화 → UI·외부 시스템 연결 자유
- **소요 시간**: 1분

### Slide 13 — 전체 에이전트 구성 아키텍처

- **핵심 메시지**: 앞 장의 3-tier 인프라 **위에 살고 있는 모든 에이전트**가 한 장에 들어온다 — **Agent Assistant(메타) → Main Agent(사용자 정의) → SubAgent(위임 단위)** 3계층이 같은 Runner·같은 6대 기능·같은 이벤트 스택 위에서 일관 동작.
- **시각자료**: 3계층 트리(또는 동심원) 다이어그램.
  - **L1 메타 레이어** — Agent Assistant: 에이전트를 만드는 에이전트 (자연어 → 캔버스 자동 제안)
  - **L2 사용자 에이전트** — Main Agent A · B · C ...: Agent Assistant 가 자연어로 자동 조립한 운영용 에이전트
  - **L3 위임 에이전트** — SubAgent (`research` / `report-writer` / ...): Main Agent 가 호출하는 격리 컨텍스트·도구·모델 단위
  - 각 노드 옆에 6대 기능 매핑 라벨 (Mode / Skills / Tools / HITL / Todo / SubAgent 권한)
  - 좌측 공통 자산층: **Skills 카탈로그 · Tools 카탈로그(HTTP/Code/Search/MCP/Built-in) · LLM Provider**
  - 우측 공통 운영층: **권한 매트릭스 · HITL 게이트 · Todo 패널 · 감사 로그**
  - 모든 노드가 동일 WebSocket 이벤트 버스(`agent.streaming` / `step.progress` / `node.proposed` / `run.completed`)에 물려 있음을 화살표로 표시
- **말할거리**:
  - Agent Assistant 한 번이 여러 Main Agent 를 낳고, 각 Main Agent 가 여러 SubAgent 를 가짐 → **자산이 트리 구조로 누적**
  - 모든 계층이 같은 Runner·같은 6대 기능·같은 이벤트 스택 → 모니터링·감사·HITL 정책이 **에이전트 종류와 무관하게 일관**
  - SubAgent 는 독립 컨텍스트·도구·모델 → 메인 토큰 보호 + 보안 격리 (예: 외부 전송 권한을 SubAgent 에만 부여 가능)
  - Skills/Tools 는 카탈로그에서 끌어다 장착 → 한 번 만든 능력을 **조직 전체가 재사용**, Agent Assistant 가 자동 추천
  - 차별점 한 줄: "에이전트 한 마리를 잘 만든다" 가 아니라 **"에이전트 집합을 일관되게 운영한다"**
- **소요 시간**: 1분 30초

### Slide 14 — Agent Builder MVP 구현 현황

- **핵심 메시지**: 오늘 보여드린 Agent Builder 의 **핵심 기능 전부가 코드와 UI에서 동작 단계** — PoC가 아니라 **베타 직전**. Agent Assistant + 6대 기능 + 3-tier 인프라가 통합 실행되며 사내 운영 시나리오를 실제로 처리 중.
- **시각자료**: 좌 — **구현 완료 체크리스트** (아래 항목), 우 — 동작 캡처 썸네일 그리드 (Agent Assistant 채팅·캔버스 자동 조립·SubAgent 위임·HITL 카드·Skills 카탈로그). 우측 하단 캡션: "사내 Gmail/Slack/Drive 등 MCP 도구 결합 자동화 운영 중".
- **시각자료 — 구현 완료 체크리스트**:
  - **L1 메타 에이전트** ● Agent Assistant — 자연어 → 메인/서브/도구/Skill 자동 제안, 4-action 분류(clarify/create/edit/answer) 동작
  - **L2/L3 에이전트** ● Main Agent + SubAgent 위임 — 캔버스에서 시각 운영, SubAgent todo 클라이언트 복원
  - **Agent Mode** ● ReAct 실행 전략 동작 (Plan-and-Execute 는 로드맵)
  - **Tools** ● HTTP / Code / Search / MCP / Built-in 5종 동작 + **사용자별 자격증명 격리** + Tool Permission 정책
  - **HITL** ● 도구 호출 직전 게이트 + Approve / Edit / Reject UI 동작
  - **Skills** ● 카탈로그 + 버전 핀 + **사내 export/import** 동작 (최근 추가)
  - **Todo** ● 실시간 패널 + SubAgent todo list 복원
  - **3-tier 인프라** ● Next.js 16 Web (28002) / NestJS API (28001) / FastAPI Runner (28003) — LangGraph + 공식 `deepagents` 패키지
  - **WebSocket 이벤트 스택** ● `agent.streaming` / `step.progress` / `node.proposed` / `run.completed` 표준화
  - **MCP 외부 도구 연동** ● Gmail OAuth (콜백 중복 가드) / Slack / Drive 실 동작
  - **잔여(◐)**: Main Agent 컨테이너 시각화, Tool Permission 인자 제한, Jinja 변수 확장, Phase 7 잔여 4건 · Phase 8 회귀 6건 · Phase 11 후속
- **말할거리**:
  - 임원 자리에서 가장 자주 받는 질문 — "PoC인가 운영인가" — 답은 **베타 직전**
  - Agent Assistant 모듈(`agent_assistant`)은 Runner·API·Web 모두에 정식 모듈로 연결 — 별도 실험 트랙 아님
  - 잔여 작업은 모두 **회귀 검증·UX 보강** 영역 — 신규 기능 개발이 아님
  - 시연 시나리오: 실제 사내 Gmail/Slack/Drive 결합 자동화가 운영 중 — 라이브 데모 가능 (Slide 10·11 와 동일 흐름)
- **소요 시간**: 1분 30초

### Slide 15 — 향후 구현 로드맵: Knowledge Base · vLLM · Evaluation · MCP+

- **핵심 메시지**: MVP 베타 직후 6-12개월의 핵심 확장은 **Knowledge Base / vLLM / Evaluation / MCP 카탈로그 확장 + 엔터프라이즈 보안** 5개 트랙. 각 트랙은 Section 2·3 의 시장 진단과 직접 연결돼 있다 — RAG 흡수·국산화·거버넌스 측정·표준 정렬·보안 컴플라이언스.
- **시각자료**: **5개 카테고리 카드 그리드** + 각 카드에 우선순위 배지(`P0`/`P1`) 및 "왜 지금" 트리거.
  - **① Knowledge Base / Agentic RAG** `P0`
    - 사내 문서·위키 임베딩 + 벡터 검색 + 메타데이터 인용
    - **Agentic RAG** — 에이전트가 능동 검색·다중 패스 (단순 RAG 대비 Agent Builder 의 우위가 살아남)
    - *트리거*: Slide 4 의 "RAG 시장 포화" 를 위협이 아닌 **흡수 대상**(에이전트 안의 도구) 으로 전환
  - **② vLLM 연동 / 국산·자체 호스팅 LLM** `P0`
    - vLLM 기반 self-hosted 모델 서빙 통합 — Llama / Qwen 계열 + **HyperCLOVA X / Solar 등 국산 LLM** 어댑터
    - **air-gapped 배포** 시나리오 대응 (Slide 4 의 삼성 사내망 사례 같은 요구)
    - 비용 최적화 — 트래픽 큰 SubAgent 는 self-hosted, 핵심 reasoning 만 외부 SaaS
    - *트리거*: 외산 SaaS 종속을 우려하는 1차 ICP 의 마지막 보안 우려 해소 + 국산 AI 표준화 기여(Slide 16)
  - **③ Evaluation 프레임워크** `P0`
    - Judge LLM 기반 응답·플로우 평가 / **회귀 데이터셋** / A/B 비교 / 골든셋
    - 운영 지표 결합 — HITL 개입률·도구 실패율·Skill 사용 빈도·토큰/비용
    - *트리거*: **Gartner 가 지적한 거버넌스 부재 = 측정 부재** (Slide 4) — Agent 프로젝트 취소 위험의 근본 해소책
  - **④ MCP 카탈로그 확장 + A2A** `P1`
    - 사내 MCP 서버 호스팅 + 카탈로그(승인 워크플로) — 현재는 외부 MCP 연결만
    - 동적 discovery / OAuth·자격증명 매니지먼트 강화
    - **Google A2A 프로토콜 호환** 검토 (Cloud Next 2026 표준 — Agent 간 통신 표준)
    - *트리거*: 후발 표준에 끌려가지 않고 선반영 — 외산 빌더와 상호운용 가능한 위치 확보
  - **⑤ 엔터프라이즈 보안·실행 엔진 확장** `P1`
    - SSO / RBAC / **멀티테넌트 격리** / 감사 로그 export (SOC 2 대비)
    - 실행 엔진 측 — **Plan-and-Execute Mode** · **Async SubAgent** · **Backend Store**(deepagents 공식 backend)
    - *트리거*: 외부 ICP 파일럿(Slide 18) 진입 직전 필수 조건
- **말할거리**:
  - **① Knowledge Base** 가 들어오면 우리는 "RAG 가 잘하는 부분까지 흡수한 Agent Builder" — 시나리오 RAG 와의 변별이 완성됨
  - **② vLLM·국산 LLM** 은 단순 모델 추가가 아니라 **국산 + 사내망(air-gapped) + 비용 최적화** 3축 동시 해결
  - **③ Evaluation** 은 운영 가능성을 정량 입증할 유일한 수단 — "측정 가능한 거버넌스" 자체가 외산 빌더 대비 차별점
  - **④ MCP+·A2A** 는 시장 표준 흐름(Anthropic MCP / Google A2A) 에 정렬 — 표준 이탈 위험 0
  - **⑤** 엔터프라이즈 보안·실행 엔진은 외부 파일럿(Slide 18) 진입 직전 필수
  - 우선순위 — **①②③ 동시 진행** (각 1명 풀타임 가정), ④⑤ 는 ②③ 결과를 보고 1분기 후반 합류
  - 단순 기능 나열이 아니라 **Slide 4 시장 진단의 빈 자리** 와 각각 1:1 매칭 — 로드맵이 시장에서 뒤따라가는 게 아니라 시장 갭을 메우는 순서
- **소요 시간**: 2분

### Slide 16 — 기대효과 & 사회적 기여

- **핵심 메시지**: 정량으로는 에이전트 구축·운영 비용을 줄이고, 정성으로는 통제권·자산화를 가져오며, **사회적으로는 국산 AI 운영 인프라 표준화·중소조직 AI 접근성 향상에 기여**한다. **Agent Assistant 가 구축 비용 절감 효과의 주역**.
- **시각자료**: 좌(정량) / 중(정성) / 우(**사회적 기여**) 3분할.
  - 좌 — 가정치 카드 3장: "**에이전트 구축 리드타임 ↓↓ (Agent Assistant)**", "운영 인시던트 ↓ (HITL·권한)", "Skill 재사용으로 중복 작업 ↓" (수치는 docx 작성 시 확정)
  - 중 — 정성 키워드: "비개발자 셀프 빌드", "통제권 회수", "조직 학습 자산화", "감사 추적", "벤더 의존 ↓"
  - 우 — **사회적 기여 카드 3-4장**:
    - **국산 AI 운영 인프라 표준화** — 외산 SaaS 종속 없이 국내 조직이 통제권을 가진 AI 운영 환경 확산
    - **중소·중견 조직 AI 접근성** — 비개발자도 자연어로 에이전트를 만들 수 있어 대기업·전문 조직 외에도 도입 가능
    - **AI 활용의 책임성·감사 추적성 강화** — HITL·도구 권한·감사 로그로 "설명 가능한 AI 운영" 구조 제공
    - **AI 시대 일자리 변화 대응** — 단순 반복 업무는 에이전트가 수행하고 사람은 감독·기획 역할로 전환 (HITL 이 그 인터페이스)
- **말할거리**:
  - 정량 수치는 docx 단계에서 사내 사례·벤치마크와 함께 확정 — 오늘은 방향 공유
  - 구축 리드타임은 Agent Assistant 로 가장 크게 단축 가능 — 비개발자도 셀프 빌드
  - 정성 효과는 1차 ICP가 가장 절실하게 원하는 부분
  - 사회적 기여는 단순 부수효과가 아니라 **공공·정책 평가에서 직접 평가 항목** — 국산 표준화·접근성·책임성 키워드를 발표 자리에서 명시
  - "비용 절감"보다 "운영 가능"이 1차 가치, 그 위에 "**국내 AI 도입의 격차 해소**" 가 사회적 메시지
- **소요 시간**: 1분 30초

## Section 5 — 성장가능성 (4장 / 5분) [DOCX §4]

### Slide 17 — BM 옵션 & 가치전달구조

- **핵심 메시지**: **가치사슬** (데이터·도구·LLM → AgentStudio 운영 레이어 → 고객 업무 산출물 → 운영 신호 피드백) 위에서 라이선스·구독·SI 3안을 **고객 성숙도에 맞춰 단계별로** 제공한다.
- **시각자료**: 상·하 2단 구성.
  - **상단 — 가치전달구조 다이어그램 (좌→우 흐름)**:
    1. **인풋 자산** — 사내 데이터 · 사내 도구/API · 외부 MCP 도구 · LLM Provider (OpenAI/Anthropic/Google 등)
    2. **AgentStudio 운영 레이어** — Agent Assistant(빌드) + 6대 기능(통제·감독·자산화) + Runner(실행) + 감사·모니터링
    3. **고객 업무 산출물** — 자동화된 워크플로우 결과 (영업 리서치·고객 응대·내부 리서치·운영 자동화 등)
    4. **운영 신호 피드백 루프** — 사용 로그·HITL 개입 패턴·Skill 사용 빈도가 다시 인풋 자산을 강화 (조직 학습)
    - 각 단계 아래 "우리가 가져가는 마진/책임 지점" 표시: 운영 레이어 = 우리 영역, 좌우는 고객·제3자 자산
  - **하단 — 3단 가격 카드** (라이선스형 / 구독형 / SI 결합형) + 각 카드 아래 타깃 고객 유형 + 매출 인식 방식(연간 라이선스 / 월 구독 / 프로젝트 + 유지보수)
- **말할거리**:
  - 가치사슬에서 **우리가 가져가는 위치 = 운영 레이어** — LLM/데이터를 만들지 않고 그 위에서 통제·자산화를 제공
  - 피드백 루프가 핵심 자산 — 고객사 사용량이 늘수록 우리 운영 노하우·기본 Skill 카탈로그가 함께 성장
  - BM 3안:
    - 초기 — 사내 사용 + 그룹사 라이선스 (운영 신호 확보)
    - 중기 — SaaS 구독 (사용량·시트 기반)
    - 대형 — SI 결합 (보안 요구 충족 + 매출 두꺼움)
  - 가격대 수치는 docx 단계 확정 — 오늘은 **수익 인식 구조와 타깃 매핑**만 합의
- **소요 시간**: 1분 30초

### Slide 18 — Go-to-Market 시나리오

- **핵심 메시지**: 사내 → 그룹사 → 외부 — 3단 점프로 시장에 진입한다.
- **시각자료**: 3단 깔때기 — 사내 도그푸딩 → 그룹사 파일럿 1-2건 → 외부 ICP 파일럿 → 정식 상용. 각 단계의 성공 기준 1개씩 라벨.
- **말할거리**:
  - 1단계 (현재): 사내 운영 사례 1-2개 — 운영 데이터 확보
  - 2단계: 그룹사 1-2곳 파일럿 — 보안·SI 요구 검증
  - 3단계: 외부 ICP 파일럿 — 가격 검증
  - 단계마다 **외부에 보여줄 운영 신호**가 자산
- **소요 시간**: 1분

### Slide 19 — 로드맵 (1-2분기): Slide 15 5개 트랙을 시간축에 배치

- **핵심 메시지**: 다음 2분기는 **회귀 안정화 + Slide 15 의 5개 확장 트랙(KB·vLLM·Eval·MCP+·엔터프라이즈 보안) + 운영 사례 확보**가 동시 진행된다. Slide 15 가 "무엇을 / 왜" 라면, 본 슬라이드는 "**언제 / 누가 / 트랙 분리**".
- **시각자료**: 3-트랙 간트 (가로축 = 1Q / 2Q).
  - **① 안정화 트랙** — Phase 7 잔여 4건 · Phase 8 회귀 6건 · Phase 11 후속 (1Q 전반 마무리)
  - **② 확장 트랙** (Slide 15 의 5개 P0/P1 카테고리)
    - 1Q: `P0` ① Knowledge Base · ② vLLM·국산 LLM · ③ Evaluation 동시 착수 (각 1명 풀타임)
    - 2Q: `P1` ④ MCP+·A2A · ⑤ 엔터프라이즈 보안(SSO/RBAC/멀티테넌트) + 실행 엔진 확장(Plan-and-Execute / Async SubAgent / Backend Store) 합류
  - **③ 운영 트랙** — 사내 파일럿 1건(1Q) → 그룹사 파일럿 후보 발굴(1Q 후반) → 그룹사 파일럿 1-2건 진행(2Q)
- **말할거리**:
  - 안정화와 확장이 서로를 막지 않도록 트랙 분리 — 안정화는 회귀·UX, 확장은 신규 능력
  - **확장 트랙 5개의 우선순위 근거는 Slide 15 의 시장 갭 매칭** — 본 슬라이드는 그것의 시간 배치
  - 트랙 ③ 운영은 영업·CS와 공동 책임 — 외부 시그널 확보가 자산
  - 인력 배치·정확한 마일스톤 일자는 docx 단계 OKR 과 함께 확정
- **소요 시간**: 1분 30초

### Slide 20 — KPI / 성공 지표

- **핵심 메시지**: "운영되는 에이전트 수" 와 "재사용되는 자산 수" 를 **단일 북극성 지표**로 본다. **Agent Assistant 채택률**도 핵심 보조 지표.
- **시각자료**: KPI 카드 5-6개.
  - **Activation**: 1개 이상 에이전트를 정기 사용하는 팀 수
  - **Active Agents**: 일 1회 이상 실행되는 에이전트 수
  - **Assistant-Built Ratio**: Agent Assistant 로 만들어진 에이전트 비율 (셀프 빌드 채택률)
  - **Reused Skills**: 2개 이상 에이전트에 장착된 Skill 수
  - **HITL Intervention Rate**: 위험 행동에서 사람이 실제로 가로챈 비율
  - **External Pilots**: 외부 파일럿 진행/완료 수
- **말할거리**:
  - "잘 만들었나"가 아니라 "실제로 운영되나"를 본다
  - Assistant-Built Ratio 가 높아진다 = 비개발자가 진짜로 쓰고 있다는 신호
  - HITL 개입률은 양면 지표 — 너무 높으면 자동화 효용↓, 너무 낮으면 통제 형식적 → 적정 밴드 모니터
  - 정확한 KPI 목표 수치는 분기 OKR에서 확정
- **소요 시간**: 1분
