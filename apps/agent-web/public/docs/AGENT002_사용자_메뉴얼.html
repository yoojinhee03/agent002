AGENT002

AI Agent Management Platform

대상: 빌더 사용자 + 챗 클라이언트 사용자 버전: v1.1

1. 서비스 개요

AGENT002는 LangGraph 기반의 AI 에이전트를 시각적으로 설계·실행·배포할 수 있는 엔터프라이즈 플랫폼입니다. 좌측 상단 로고와 앱 메타 타이틀·로그인 화면 타이틀 모두 "AGENT002" v1.0.0으로 표기됩니다.

플랫폼이 제공하는 기능

  • 에이전트 빌더 — React Flow 캔버스에서 Main Agent와 Sub Agent를 시각적으로 배치하고, 우측 패널에서 프롬프트·도구·스킬·모델·가드레일을 설정합니다.
  • 인라인 실행/디버그 — 캔버스 안에서 바로 실행해 단계별 이벤트와 노드 활성화를 시각적으로 확인합니다.
  • 버전 관리 배포 — 환경(Environment)별로 v1, v2, …처럼 버전이 매겨진 배포를 관리합니다.
  • API 키 발급 — 외부 시스템에서 호출하기 위한 키를 배포 단위로 발급/폐기합니다.
  • 챗 클라이언트 — 배포된 에이전트를 일반 사용자에게 채팅 UI(/client)로 제공합니다.
  • Skills · Tools 관리 — 재사용 가능한 스킬·도구를 별도 화면에서 관리하고, 에이전트별로 선택적으로 활성화합니다.
  • 관측성 — Usage(사용량) / Monitoring(모니터링) 대시보드로 운영 상황을 추적합니다.
  • 연동 — Slack 통합 (관리자 전용).

이 메뉴얼의 대상 독자

  • 빌더 에이전트를 만들고 배포하는 사람 → 5~11장
  • 사용자 챗 클라이언트로 사용하는 사람 → 12장
  • 관리자 권한이 admin인 사람 → 11장 (Users · Slack 추가)

2. 시작하기

2.1 권장 환경

  • 최신 버전의 Chrome / Edge / Safari / Firefox
  • 1280 × 800 이상의 해상도
  • 안정적인 네트워크 (실시간 실행 결과를 SSE로 전달받음)

2.2 로그인

웹 브라우저에서 서비스 주소로 접속하면 자동으로 /login으로 이동합니다. 이미 인증된 세션이 있으면 /dashboard로 바로 진입합니다.

STEP 1이메일 입력 (placeholder: user@example.com)
STEP 2비밀번호 입력 — 우측 눈 아이콘으로 표시 토글
STEP 3로그인 버튼 클릭 또는 Enter

실패 시 카드 상단에 빨간 안내가 표시됩니다.

  • "이메일과 비밀번호를 입력해주세요." — 필드 비어 있음
  • "이메일 또는 비밀번호가 올바르지 않습니다." — 인증 실패

2.3 비밀번호 재설정

  1. 로그인 화면 하단 비밀번호를 잊으셨나요? 클릭
  2. "비밀번호 찾기" 화면에서 이메일 입력 → 메일 전송
  3. "메일이 전송되었습니다" 안내가 뜨면 비밀번호 재설정 클릭
  4. 새 비밀번호(6자 이상)와 확인을 입력하고 비밀번호 변경 클릭
  5. 변경 완료 후 로그인으로 이동을 눌러 새 비밀번호로 로그인

4. 핵심 개념

본격적인 사용에 앞서 다음 9가지 개념을 이해해 두면 화면이 훨씬 명확해집니다.

4.1 Project (프로젝트)

모든 자원(에이전트·스킬·도구·배포 등)은 프로젝트 단위로 격리됩니다. 사용자가 로그인하면 자동으로 "활성 프로젝트(activeProjectId)"가 설정되며, 화면 좌상단 또는 컨텍스트에서 전환할 수 있습니다. "활성화된 프로젝트가 없습니다. 초기화 중..." 메시지가 보이면 잠시 후 자동 복구됩니다.

4.2 Agent (에이전트)

하나의 LangGraph 기반 에이전트 정의입니다. 단일 에이전트는 Main Agent만 있고, 멀티에이전트는 Sub Agent 노드를 추가해 협업 그래프를 구성합니다. 카드의 우상단에 보라색 Multi-agent 배지가 있으면 멀티에이전트입니다.

4.3 Harness / Graph Definition

에이전트의 노드·엣지·구성 데이터를 합친 정의입니다. 캔버스에서 본 그대로 graphDefinition으로 저장되며, JSON으로 Import / Export 할 수 있습니다.

4.4 System Prompt

에이전트의 역할·말투·규칙을 정의하는 본문입니다. Monaco 에디터에서 작성하고 저장하면 PromptVersion이 누적되어 이전 버전으로 복원할 수 있습니다. Few-shot 메시지(user/assistant 쌍)도 추가 가능합니다.

4.5 Skill (스킬)

이름 + 설명 + instructions(지시문) + files(파일 묶음)로 구성된 재사용 가능한 작업 절차입니다. 스킬 단위로 allowedTools(이 스킬이 사용할 수 있는 도구)를 지정합니다.

4.6 Tool (도구)

3가지 분류가 있습니다.

  • Custom Tool — 빌더의 ToolBuilder Wizard로 직접 만든 도구
  • MCP Tool — 외부 MCP 서버에 등록된 도구
  • Builtin Tool — 플랫폼이 기본 제공하는 도구(search, google, utilities 등)

도구별로 정책(allow / ask / deny)을 설정할 수 있어 권한을 세밀하게 통제합니다.

4.7 Brain Model

에이전트가 사용할 LLM 모델입니다. 모델은 먼저 Providers 화면에서 활성화되어야 선택지에 나타납니다. Temperature(0~2), Max Tokens(256~32768)는 모델 탭의 슬라이더로 조절합니다.

4.8 Environment (환경) · Deployment (배포)

환경은 dev / staging / prod처럼 운영 단계를 구분합니다. 에이전트를 환경에 배포하면 v{버전}이 자동 부여되며, 각 배포는 고유한 publicPath와 별도의 API 키 묶음을 가집니다.

4.9 Thread / Message

챗 클라이언트의 대화 단위입니다. 메시지를 보내면 thread가 만들어지고, 첫 메시지의 첫 40자가 자동 제목이 됩니다. 상태는 active / archived 두 가지이며, 사이드바 우클릭 → 삭제로 archive 됩니다.

5. 빌더 가이드 빌더

5.1 Dashboard (/dashboard)

로그인 후 처음 보이는 화면입니다. 상단에는 요약 카드(Summary)가, 아래에는 사용량 차트(UsageChart), 토큰/비용 차트(TokenCostChart), 에이전트 상태 표(AgentStatusTable), 상위 에이전트 차트(TopAgentsChart)가 표시됩니다. 우상단 SourceToggle로 데이터 소스(범위)를 전환할 수 있습니다.

5.2 Agents 목록 (/agents)

좌측 메뉴 Agents를 누르면 진입합니다.

에이전트 카드 구성

위치표시 항목

Import (JSON 가져오기)

우상단 ⬆ Import를 누르면 파일 선택 다이얼로그가 열립니다. JSON 파일을 선택하면 그대로 새 에이전트로 추가됩니다. 잘못된 형식이면 "유효한 에이전트 파일이 아닙니다", JSON 파싱 실패 시 "JSON 파싱에 실패했습니다" 토스트가 표시됩니다.

5.3 New Agent 만들기

우상단 파란색 + New Agent 버튼을 누르면 모달이 열립니다.

  1. 이름을 입력합니다. 비어 있으면 생성 버튼이 비활성화됩니다.
  2. 설명을 입력합니다 (선택).
  3. 에이전트 생성을 누르면 에이전트가 만들어지고 자동으로 빌더 캔버스로 이동합니다.
생성 시 자동 적용되는 기본값 systemPrompt = "You are a helpful assistant." / modelId = "gpt-4o-mini"
이후 캔버스에서 자유롭게 변경 가능합니다.

5.4 Agent Builder 캔버스 (/agents/[agentId])

에이전트의 모든 구성을 시각적으로 편집하는 화면입니다.

상단 툴바

위치버튼/표시동작
좌측← Agents이전 화면으로 이동
좌측에이전트명현재 편집 중인 에이전트 이름
좌측주황 미저장변경이 있고 저장 전인 상태
우측🚀 배포배포 관리 페이지로 이동
우측⚙ Main AgentMain Agent 모달 열기 (이름/설명/Brain Model)
우측▶ 실행현재 캔버스 상태로 실행 시작

중앙: React Flow 캔버스

  • Main Agent 노드: 항상 1개. 좌상단 (300, 150) 위치에 자동 생성.
  • Sub Agent 노드: 멀티에이전트일 때 추가. 우클릭/도구로 새 노드 생성.
  • 엣지: 노드 간 연결선. 실행 시 활성 엣지가 파란색으로 표시.
  • 노드를 클릭하면 우측 패널이 해당 노드의 설정을 보여줍니다.

우측 패널 (가변 폭)

우측 패널은 3가지 모드로 전환됩니다.

  • Settings — 노드별 8개 탭 (기본 동작, 다음 절에서 자세히)
  • Debug — 실행 결과·이벤트 스트림 (실행 시 자동 전환)
  • Assistant Log — Agent Assistant가 생성한 변경 이력

패널 좌측 가장자리를 드래그해 폭을 320~800px 사이에서 조절할 수 있고, 값은 브라우저에 기억됩니다.

하단: Agent Assistant 패널

자연어로 캔버스 편집을 요청하면 변경 제안을 카드로 보여줍니다. (5.9에서 자세히)

5.5 Main Agent 모달

툴바의 ⚙ Main Agent를 누르면 작은 모달이 열립니다.

각 필드에서 포커스를 잃으면(blur) 즉시 변경이 캔버스에 반영되며 "미저장" 배지가 켜집니다. 실제 저장은 툴바의 💾 저장을 눌러야 영구화됩니다.

5.6 Settings 패널 — 8개 탭

캔버스에서 노드를 선택하면 우측 Settings 패널의 탭 목록이 활성화됩니다.

탭내용
기본이름·설명·아키텍처(react / supervisor / custom_graph) 등 기본 정보

프롬프트 탭 자세히

  • Monaco 에디터로 자유 편집. 외부에서 prompt가 갱신되면 자동 동기화됩니다.
  • 상단의 + Few-shot 추가로 user/assistant 예시 메시지를 추가할 수 있습니다.
  • 우상단 🕒 Versions를 누르면 이전 버전 목록이 펼쳐지고, 클릭으로 복원 가능합니다.
  • 변수 그룹({{...}})이 정의되어 있으면 화면 한쪽에 변수 도우미가 함께 표시됩니다.

도구 탭 자세히

  • 그룹: Custom · MCP · Builtin · Teammates(서브 에이전트 도구)
  • 그룹별 아이콘 예: 🔍 search, 🌐 google, ⚙ utilities
  • 각 항목 옆 체크박스로 활성/비활성
  • 활성화한 도구는 ToolPermissionsPanel에서 정책을 별도 설정합니다 (allow / ask / deny)

모델 탭 자세히

  • Brain Model — Providers에서 활성화한 모델 중 선택. 활성 모델이 없으면 현재 modelId 또는 "모델 없음"이 표시됩니다.
  • Temperature — 0(정확) ~ 2(창의), 기본 0.7. 슬라이더 우측에 현재 값이 파란색으로 강조 표시.
  • Max Tokens — 256 ~ 32,768 (step 256), 기본 4096.

5.7 Sub Agent 추가 / 멀티에이전트 구성

  1. 캔버스에서 노드 추가 도구(+ 아이콘 또는 우클릭 메뉴)로 Sub Agent 노드를 생성합니다.
  2. 새 Sub Agent 노드를 클릭하면 우측 패널이 해당 Sub Agent의 설정으로 전환됩니다.
  3. Sub Agent에도 이름·설명·시스템 프롬프트·모델·도구·스킬을 각각 설정합니다.
  4. Main Agent ↔ Sub Agent 사이를 드래그해 엣지를 연결합니다.
  5. Sub Agent 노드 우상단의 X 또는 컨텍스트로 삭제할 수 있으며, 삭제 시 관련 엣지도 함께 제거됩니다.
  6. 저장하면 카드 우상단에 보라색 ⌬ Multi-agent 배지가 붙고, 카드 칩에 "서브 N"이 추가됩니다.
언제 멀티에이전트를 쓰나요? 한 가지 큰 작업을 여러 단계로 나누거나(조사→작성→검토), 서로 다른 전문 지식이 필요할 때 효과적입니다. 단순 Q&A는 단일 에이전트가 더 빠르고 단순합니다.

5.8 캔버스 실행 (Debug)

  1. 툴바의 파란 ▶ 실행을 누릅니다.
  2. 우측 패널이 Debug 모드로 자동 전환되고 입력창이 열립니다.
  3. 사용자가 보낼 법한 질문을 입력하고 전송합니다.
  4. 실행 중에는 캔버스의 노드와 엣지가 활성화됨에 따라 색이 변합니다.
    • 기본: 흰색 반투명 테두리
    • 활성: 파란색 (#60A5FA)
    • 오류: 빨간색 (#EF4444)
  5. Debug 패널에서 단계별 이벤트, 도구 호출, 토큰 사용량 등을 확인합니다.
  6. 다시 실행하려면 같은 버튼을 다시 누릅니다.

5.9 Agent Assistant 패널

캔버스 하단의 Agent Assistant는 자연어 명령으로 에이전트 구성을 도와주는 보조 기능입니다.

  • "프롬프트를 정중한 어투로 다듬어줘", "이메일 발송 도구를 추가해줘" 등으로 요청 가능
  • 변경 제안은 ProposalApplyCard(노드 변경)와 EditApplyCard(prompt 등) 형태로 캔버스에 떠 [적용] 한 번에 반영
  • 제안을 적용하면 자동으로 "미저장" 배지가 켜지므로 저장을 잊지 마세요
  • 패널 높이는 상단 가장자리를 드래그해 120~600px 사이에서 조절 가능 (브라우저에 기억됨)

5.10 저장 · Import · Export

저장

툴바의 💾 저장을 누르면 캔버스 상태(graphDefinition)와 변경된 필드가 일괄 저장됩니다. 저장 중에는 회전 아이콘이 표시되며, 완료 후 "미저장" 배지가 사라집니다.

Import

/agents 목록 우상단의 ⬆ Import로 다른 환경에서 내보낸 JSON 파일을 불러올 수 있습니다.

Export

각 에이전트 카드의 컨텍스트 메뉴 또는 빌더의 내보내기 기능을 통해 JSON으로 백업할 수 있습니다.

6. Skills 관리 (/skills) 빌더

스킬은 에이전트가 사용할 수 있는 재사용 가능한 작업 절차입니다.

6.1 스킬 생성/편집

  1. + New Skill 클릭 → 폼이 열립니다.
  2. 입력 항목:
    • name — 스킬 이름
    • description — 무엇을 하는 스킬인지 한 줄 요약
    • instructions — 스킬의 본문(보통 Markdown). 첫 비어있지 않은 줄이 카드 미리보기로 사용됩니다.
    • allowedTools — 이 스킬이 호출 가능한 도구 목록
  3. 저장 시 "Skill이 생성되었습니다" / "Skill이 수정되었습니다" 토스트가 표시됩니다.

6.2 파일 첨부

편집 화면에서 스킬에 파일을 첨부할 수 있습니다. 지원되는 확장자 일부:

  • 코드: .py .ts .js .sh
  • 문서: .md .html .json .yaml/yml .toml
  • 마크업: .css .xml

각 파일은 코드 하이라이팅된 에디터로 열어 편집할 수 있습니다.

6.3 Import / Export

  • Export: 카드 우상단 ⬇ 내보내기 (JSON) 아이콘 — 파일명: {name}.skill.json
  • Import: 우상단 Import 버튼 — 유효한 agentstudio.skill 타입 파일만 허용

6.4 상대시간 표시

카드의 갱신 시각은 "오늘 / 어제 / N일 전 / N주 전 / N달 전 / N년 전"으로 표시됩니다.

7. Tools 관리 (/tools) 빌더

좌측 메뉴 Tools는 3개 탭으로 구성됩니다.

탭설명
CustomToolBuilder Wizard로 직접 만든 도구. ToolGroup으로 묶어 관리.
MCP외부 MCP 서버를 등록하고, 카탈로그(McpCatalogPanel)에서 사전 정의된 서버를 추가 가능.
Builtin플랫폼이 기본 제공하는 도구. 활성/비활성만 가능.

7.1 Custom Tool 만들기

  1. Custom 탭에서 + 도구 추가 → ToolBuilderWizard 시작
  2. 이름·설명·입력 스키마·실행 방식(HTTP 등)을 단계별로 입력
  3. 저장하면 Custom 탭에 카드 형태로 표시
  4. 여러 도구를 묶으려면 📁 ToolGroup 만들기로 그룹화

7.2 MCP 서버 등록

  1. MCP 탭에서 + MCP 서버 추가
  2. 모달에서 서버 URL, 인증 정보(McpCredentialMode), 이름 등을 입력
  3. 등록 후 카드 형태로 표시되고, 서버가 제공하는 도구 목록이 노출됨
  4. 또는 McpCatalogPanel에서 사전 정의된 서버를 한 번에 추가

7.3 Builtin Tools

BuiltinToolsPanel에서 각 도구의 활성/비활성을 토글할 수 있습니다. 그룹 예: search, google, utilities 등.

8. Providers · 모델 관리 (/settings/providers)

좌측 메뉴 Providers에서 LLM 프로바이더(OpenAI, Anthropic 등)별 API 키를 등록하고 사용할 모델을 활성화합니다. 여기서 활성화된 모델만 빌더의 Brain Model 셀렉트에 나타납니다.

9. 배포 (Deployments) (/agents/[agentId]/deployments)

9.1 새 배포

  1. 환경을 선택합니다. 사용 가능한 환경이 없으면 "먼저 프로젝트 환경을 생성해주세요." 안내가 표시됩니다.
  2. 설명(선택): 릴리스 노트로 사용됩니다.
  3. 🚀 배포 실행을 누르면 "v{version} 배포 완료" 토스트가 뜨고 배포 이력에 새 행이 추가됩니다.

9.2 배포 이력

컬럼설명
선택라디오 버튼 — 이 배포를 현재 선택으로 지정 (API 키 관리 대상)
버전v1, v2, ... (자동 증가)
환경{environment name} ({slug})
상태active(녹) / inactive(회) / pending_approval(주) / failed(빨) / revoked(빨)
publicPath호출 시 사용하는 경로 (복사 아이콘으로 즉시 복사)
설명릴리스 노트
배포 시각YYYY-MM-DD HH:MM
동작active 상태에서 [비활성화] 가능

9.3 API 키

선택된 배포에 대해 API 키를 발급/관리합니다.

  1. + 키 발급 클릭 → 키 이름 입력 → 발급
  2. 발급 직후에만 노란 카드로 rawKey가 표시됩니다. 다시 조회 불가이므로 즉시 복사해 보관하세요.
  3. curl 예시(스레드 생성 → 메시지 전송)가 함께 표시되어 그대로 복사해 사용할 수 있습니다.
  4. 발급된 키는 키 목록에서 [폐기]로 즉시 무효화 가능 (되돌릴 수 없음)
비활성화 vs 폐기 배포 비활성화는 트래픽만 끊는 것이고, API 키 폐기는 해당 키 자체를 영구 무효화합니다.

9.4 호출 예시 (curl)

# 1) thread 생성
curl -X POST {API_BASE}/api/v1/chat/threads \
  -H "X-API-Key: {RAW_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"title":"first chat"}'

# 2) 메시지 전송 (응답에 받은 threadId 사용)
curl -X POST {API_BASE}/api/v1/chat/threads/{threadId}/messages \
  -H "X-API-Key: {RAW_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"content":"안녕하세요"}'

API_BASE는 현재 호스트의 origin에서 포트만 4200으로 바뀐 주소가 자동으로 채워집니다. publicPath는 발급 카드 하단에 함께 표시됩니다.

12. 챗 클라이언트 가이드 사용자

일반 사용자는 /client 영역에서 배포된 에이전트를 사용합니다.

12.1 에이전트 목록 (/client/agents)

좌측 메뉴 에이전트를 누르면 표시됩니다.

에이전트가 없으면 "사용 가능한 에이전트가 없습니다 — 관리자가 에이전트를 배포하면 여기에 표시됩니다." 안내가 표시됩니다.

12.2 에이전트 상세 (/client/agents/[slug])

카드를 클릭하면 진입합니다.

  • 상단 헤더: 에이전트 이름 · "v{version} · {env.name} · {publicPath}"
  • "← 에이전트 목록" 링크로 돌아가기 가능
  • 에이전트 카드 (아이콘·이름·설명)
  • 준비 상태 안내:
    • 자격 증명 모두 OK → 녹색 ReadyCard: "사용 준비 완료"
    • 누락 → MissingCredentialsCard: 부족한 자격 증명 안내, [도구 관리로 이동] 링크
  • AgentCompositionPanel: 메인/서브 구성, 스킬·도구 목록, 필요 자격 증명 표시
  • CredentialsCard: 등록된 자격 증명 요약

12.3 채팅 진행

  1. 준비가 완료된 에이전트에서 채팅 시작(ReadyCard 내부 액션)을 누릅니다.
  2. 채팅 화면이 열리고, 일반 메신저처럼 메시지를 입력해 전송합니다.
  3. 첫 메시지를 보내면 thread가 생성되고, 첫 40자 정도가 자동 제목이 됩니다.
  4. 응답은 스트리밍으로 화면에 도착하며, 도구 호출 시 호출 정보가 함께 표시됩니다.
  5. 대화 중 starters(추천 질문)나 첨부 등 보조 UI를 활용할 수 있습니다.
좋은 질문의 구성 맥락 + 요청 행동 + 원하는 결과 형태를 함께 적으면 정확도가 올라갑니다.
예) "지난주 회의록을 바탕으로 다음 주 임원 보고용 1페이지 요약을 한국어로 작성해줘. 주요 지표 3가지 강조."

12.4 채팅 히스토리 (/client/history)

좌측 사이드바의 thread 목록을 클릭하면 해당 대화로 진입합니다. URL은 /client/history?threadId={id} 형식이며, 같은 thread를 새 탭에서 열 수 있습니다.

  • 아직 첫 메시지가 없는(placeholder 제목 "{에이전트명} 대화") thread는 목록에서 자동 숨김
  • 관리자 디버그용 thread(source: admin-debug)도 클라이언트에서 숨김
  • 사이드바 항목 우클릭 → 🗑 삭제 (archive)
  • 상단 🔍 검색으로 제목 또는 에이전트명 부분 일치 필터

12.5 도구 관리 — 자격 증명 (/client/tools)

사용자별로 필요한 자격 증명을 등록합니다. (예: Google OAuth 연결) 상세 화면에서 누락된 자격 증명이 표시되면 이 화면으로 와서 등록을 완료해야 채팅이 가능합니다.

13. 모범 사례

빌더용 모범 사례 빌더

  • 역할은 좁고 명확하게 — 하나의 에이전트에 너무 많은 역할을 담지 말고, 역할이 다르면 분리.
  • 도구·스킬은 적정량으로 — 너무 많으면 선택 혼동이 생김. 핵심 1~3개로 시작.
  • 테스트 세트 유지 — 대표 질문 5~10개를 두고 변경마다 같은 입력으로 재테스트.
  • 버전 활용 — 프롬프트 변경 시 항상 Versions에 기록되므로 안심하고 실험. 잘못되면 즉시 복원.
  • 최소 권한 도구 — 도구 권한은 늘 가장 좁은 범위로.
  • 환경 분리 — dev에서 검증 → staging → prod 순으로 배포. 각 환경별로 API 키를 별도 발급.
  • API 키 백업 — 발급 직후 안전한 비밀 관리 시스템(1Password, Vault 등)에 저장.

사용자용 모범 사례 사용자

  • 맥락 포함 — 사용 중인 자료/상황/목적을 함께 제공.
  • 형식 명시 — 표·목록·메일 초안 등 결과 형태를 지정하면 품질 향상.
  • 단계적 진행 — 너무 많은 요청을 한 번에 묶지 말고 단계별로.
  • 중요한 결과는 검토 — 수치·법적·의료 정보는 반드시 사람이 한 번 확인.

15. 자주 묻는 질문

Q1. "AGENT002"는 어디에 표기되나요?

좌측 사이드바 로고, 앱 메타 타이틀, 로그인 화면 모두 "AGENT002"로 통일되어 표기됩니다.

Q2. Workflows / Knowledge / Evaluation 메뉴를 못 누르겠습니다.

현재 [준비 중] 상태로 비활성화되어 있습니다. 활성화 시 시각적 표시가 바뀝니다.

Q3. 배포한 에이전트를 수정해도 되나요?

네. 빌더에서 수정 후 다시 배포하면 새 버전(v+1)이 생성됩니다. 기존 버전은 그대로 보존됩니다. 필요 시 이전 버전으로 트래픽을 되돌릴 수 있도록 배포 이력에서 "선택" 라디오를 이용할 수 있습니다.

Q4. API 키를 잃어버렸어요.

다시 조회할 수 없습니다. 잃어버린 키는 [폐기]하고 새로 발급하세요.

Q5. 멀티에이전트는 꼭 써야 하나요?

아닙니다. 단일 에이전트로 충분한 경우가 더 많습니다. 작업이 단계로 명확히 나뉘거나 서로 다른 전문성이 필요할 때 효과적입니다.

Q6. 자격 증명을 등록했는데도 "누락" 안내가 사라지지 않습니다.

도구 관리 화면을 한 번 새로고침하거나, 에이전트 상세로 돌아가 한 번 더 진입해 보세요. 여전하면 등록한 자격 증명의 스코프(권한 범위)가 부족할 수 있습니다.

Q7. 사이드바를 접고 싶어요.

좌하단 ◀ 버튼으로 접을 수 있습니다. 접으면 폭 56px로 줄고 아이콘만 표시됩니다. 같은 버튼으로 다시 펼칠 수 있습니다.

Q8. 캔버스 패널 폭이 매번 초기화돼요.

드래그로 조절한 폭은 브라우저의 localStorage에 저장됩니다. 시크릿 창이나 다른 브라우저에서는 매번 초기값(460px)으로 시작합니다.

Q9. 빠른 채팅(/agents/[id]/chat)과 클라이언트 채팅은 무엇이 다른가요?

빠른 채팅은 빌더용 디버그 화면으로 admin-debug 마커가 붙은 thread를 생성하며 클라이언트 사이드바에는 노출되지 않습니다. 실제 사용자가 보는 채팅은 /client/agents/[slug]를 통해 진입한 화면입니다.
