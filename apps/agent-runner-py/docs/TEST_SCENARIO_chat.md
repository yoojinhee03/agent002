# 입사 서류 검토 에이전트 — 채팅 대화 테스트 시나리오

현재 구현된 도구: `gmail_search`, `gmail_fetch`
미구현 도구 (대화로 확인): `Document_PreProcess`, `Candidate_DB`, `Gmail_Send`

---

## SCENARIO 01 — 정상 전체 흐름 (Happy Path)

### STEP 1. 검색 및 선택

**사용자:**
```
어제 받은 입사 서류 메일 찾아줘
```

**확인 포인트:**
- `gmail_search` 도구 호출 여부
- 파라미터: `q`에 날짜 조건 포함 (예: `after:2026/04/19 has:attachment`)
- 응답에 메일 목록 (id, subject, from, date) 포함 여부

---

**사용자:**
```
두 번째 메일로 진행해줘
```

**확인 포인트:**
- 에이전트가 선택한 메일 id를 기억(상태 유지)하는지 확인
- 다음 단계(`gmail_fetch`)로 자연스럽게 이어지는지 확인

---

### STEP 2. 첨부파일 다운로드 및 분석

**사용자:**
```
그 메일 첨부파일 전부 가져와서 서류 종류 확인해줘
```

**확인 포인트:**
- `gmail_fetch` 도구 호출 여부
- 파라미터: `include_attachments: true`
- 응답의 `attachments` 배열에 `filename`, `mimeType`, `size` 포함 여부
- 9종 서류 식별 결과를 텍스트로 요약하는지 확인

**기대 응답 예시:**
```
첨부파일 7개를 확인했습니다.
- 주민등록등본.pdf (application/pdf, 234KB)
- 건강보험자격득실확인서.pdf (application/pdf, 189KB)
- 이력서.pdf (application/pdf, 512KB)
- 통장사본.jpg (image/jpeg, 98KB)
- 자격증_정보처리기사.pdf (application/pdf, 156KB)
...
누락 서류: 원천징수영수증, 차량등록증 (2종 미제출)
```

---

### STEP 3. 초안 작성

**사용자:**
```
검토 결과를 바탕으로 지원자에게 보낼 피드백 메일 초안 작성해줘
```

**확인 포인트:**
- 분석 결과(합격/보완 항목)를 종합한 메일 초안 생성 여부
- 수신자, 제목, 본문 구조 포함 여부
- 정중한 비즈니스 말투 사용 여부

**기대 응답 예시:**
```
[메일 초안]
수신: applicant@email.com
제목: [○○회사] 입사 서류 검토 결과 안내

안녕하세요, ○○○님.
입사 서류를 제출해 주셔서 감사합니다.

검토 결과, 아래 서류의 보완이 필요합니다.
- 원천징수영수증: 미제출
- 차량등록증: 미제출

위 서류를 ○월 ○일까지 제출해 주시면 감사하겠습니다.
...
```

---

### STEP 4. 검토 및 수정 승인 (Human-in-the-Loop)

**사용자:**
```
마지막 문단을 "가능한 빨리 제출 부탁드립니다"로 바꾸고 승인할게
```

**확인 포인트:**
- 에이전트가 수정 요청을 반영하여 초안을 재출력하는지 확인
- 승인 의사를 받은 뒤 다음 단계(발송)로 넘어가는지 확인
- 승인 없이 자동 발송하지 않는지 확인 (Human-in-the-Loop 준수)

---

### STEP 5. 최종 발송

**사용자:**
```
승인. 지금 바로 보내줘
```

**확인 포인트:**
- `Gmail_Send` 도구 호출 여부 (현재 미구현 → 미구현 안내 메시지 확인)
- 발송 대상, 제목, 본문이 STEP 4 승인본과 동일한지 확인
- 발송 완료 후 종료 메시지 출력 여부

---

## SCENARIO 02 — 서류 미첨부 케이스

**사용자:**
```
오늘 받은 김철수 입사 서류 메일 분석해줘
```

→ `gmail_search` 호출

**사용자:**
```
첫 번째 메일로 해줘
```

→ `gmail_fetch` 호출 → 첨부파일 0개

**기대 응답:**
```
해당 메일에 첨부파일이 없습니다.
첨부파일이 포함된 메일을 다시 확인해 주시겠어요?
```

**확인 포인트:**
- 빈 `attachments` 배열 처리 여부
- 에러 없이 안내 메시지로 graceful하게 처리되는지 확인

---

## SCENARIO 03 — 검색 결과 없음 케이스

**사용자:**
```
박영희 입사 서류 메일 찾아줘
```

**기대 응답:**
```
"박영희" 관련 입사 서류 메일을 찾지 못했습니다.
검색 조건을 바꿔볼까요? (날짜 범위, 발신자 주소 등)
```

**확인 포인트:**
- `resultSizeEstimate: 0` 응답 처리 여부
- 사용자에게 재검색 유도 여부

---

## SCENARIO 04 — 암호화 PDF 케이스

**사용자:**
```
이 메일 첨부파일 분석해줘
```

→ `gmail_fetch` 호출 → 첨부파일 중 암호화된 PDF 포함

**기대 응답:**
```
주민등록등본.pdf 파일이 암호화되어 있습니다.
비밀번호(일반적으로 지원자 생년월일 6자리)가 필요합니다.
Document_PreProcess_Tool로 잠금 해제를 시도할까요?
```

**확인 포인트:**
- PDF 암호화 감지 및 안내 여부
- `Document_PreProcess_Tool` 호출 흐름 유도 여부 (미구현 시 안내)

---

## SCENARIO 05 — 중간에 다른 메일로 변경

**사용자:**
```
첫 번째 말고 세 번째 메일로 바꿔서 다시 분석해줘
```

**확인 포인트:**
- 이전 메일 id를 버리고 새 id로 `gmail_fetch` 재호출 여부
- 상태(state)가 올바르게 교체되는지 확인
- 이전 분석 결과와 혼용되지 않는지 확인

---

## 도구별 호출 확인 체크리스트

| 단계 | 도구 | 핵심 파라미터 | 확인 항목 |
|---|---|---|---|
| 검색 | `gmail_search` | `q`, `max_results` | 날짜·키워드 자동 변환 |
| 다운로드 | `gmail_fetch` | `message_id`, `include_attachments` | 첨부파일 배열 포함 |
| 전처리 | `Document_PreProcess` | (미구현) | 안내 메시지 출력 |
| DB 조회 | `Candidate_DB` | (미구현) | 안내 메시지 출력 |
| 발송 | `Gmail_Send` | (미구현) | 승인 없이 발송 금지 |

---

## 주의사항

- **STEP 4 승인 없이 STEP 5로 넘어가면 안 됨** — Human-in-the-Loop 준수 여부가 핵심 검증 포인트
- **메일 id는 STEP 1에서 받은 값을 STEP 2에서 그대로 사용해야 함** — 상태 유지 확인
- **발송 도구 미구현 상태**이므로 STEP 5에서는 "아직 발송 기능이 연결되지 않았습니다" 안내가 정상 응답
